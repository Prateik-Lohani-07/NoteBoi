NoteBoi: code review guide

Obsidian plugin: GraphRAG over your vault on Neo4j. Generated from the live source. Files are ordered by how much they matter to the demo.

Status: tested against a real Neo4j 5 with a scripted harness (schema, ingest, hybrid retrieval, graph expansion, re-index, delete, embedding-model switch), with Ollama (gemma3:1b) and OpenAI (gpt-4o-mini), and manually in Obsidian. Not yet tested: the microphone button, Neo4j Aura, mobile (unsupported). Known weakness: graph expansion can add loosely related chunks in small vaults (no relevance cutoff yet).

How it works

Index time

.md note→chunk by heading→embed→LLM extracts concepts→Neo4j graph

Question time

question→vector + fulltext→RRF → seed chunks→Cypher expansion via concepts→LLM answers with citations→subgraph drawn
NodeMeaning
NoteA markdown file; LINKS_TO from [[wikilinks]], TAGGED from tags
ChunkA heading-bounded piece of text with an embedding; NEXT gives reading order
ConceptAn LLM-extracted idea; MENTIONS from chunks; RELATED_TO between co-occurring concepts

Where to spend your review time

  1. src/retrieve.ts: the expansion query and the "concepts connecting 2+ chunks" rule are the story you tell.
  2. src/ingest.ts: chunking, the serial write queue, and the single UNWIND write.
  3. src/neo4j.ts: how the schema survives an embedding-model switch.
  4. Skim the rest. They are plumbing.

Suggested demo question: pick one whose answer spans two notes (or two headings) that never share keywords but share a concept. The amber node in the graph is your proof that GraphRAG did something plain RAG would not.

src/retrieve.ts

184 lines

The GraphRAG core. This is what you demo.

Takes a question and returns (a) passages for the LLM and (b) the subgraph for the visualization. Everything Neo4j-specific that judges care about lives here.

Focus here

  • L51 Vector search: native Neo4j vector index, top 10 chunks by cosine similarity.
  • L58 Keyword search on the fulltext index. Catches exact terms embeddings blur (names, acronyms).
  • L64 Reciprocal Rank Fusion merges the two rankings: score = sum of 1/(60+rank). Hybrid search without tuning weights.
  • L75 THE GraphRAG step. From the seed chunks, walk (Chunk)-[:MENTIONS]->(Concept)<-[:MENTIONS]-(Chunk) to pull in related chunks that never matched the query text. Ranked by number of shared concepts. These become the amber nodes.
  • L90 Sequential neighbours: adds surrounding context from the same note.
  • L147 Visualization rule: a concept node is drawn only if it links 2+ retrieved chunks. Those are exactly the connections the graph contributed, and it keeps the picture readable.
  • L169 Grounding prompt: answer only from the notes, cite with the exact [[wikilink#heading]], say so if the answer isn't there. Each expanded passage is annotated with the concepts it was reached through.

Say this when explaining

  • Plain RAG stops at top-k similarity. Here the blue nodes are similarity hits and the amber nodes were found by walking the graph through shared concepts, so I can show where the graph changed the answer.
  • Hybrid retrieval (vector + fulltext) is fused with RRF in application code, then expanded with Cypher.
  • The viz isn't decoration: it's the exact subgraph the model was given.

Honest caveats

  • Concept quality depends on the LLM that extracted them. With a small local model, expansion can be noisy.
  • Vector index population is asynchronous in Neo4j. Right after the first index, queries can fail until the index is ONLINE.
  • Graph expansion has no relevance cutoff: in small vaults it can add loosely related chunks (e.g. NEXT neighbours), which makes the graph noisy.

src/ingest.ts

309 lines

Turns markdown into the graph.

Chunks notes by heading, embeds chunks, asks an LLM for concepts, and writes Note, Chunk, Concept, Tag nodes and their edges. Incremental: unchanged notes are skipped by hash.

Focus here

  • L14 Heading-aware chunker. This is why your giant 'Knowledge of everything' file works: it splits per heading, then packs blocks up to ~1200 chars. Code fences don't count as headings.
  • L77 Promise chain serialises every graph write, so a vault edit during a full index can't interleave and corrupt state.
  • L149 Per-note pipeline: delete old chunks, upsert note, write links, embed, extract concepts, write everything.
  • L183 Single UNWIND batch creates chunks, the HAS_CHUNK edge, Concept nodes (MERGE on lowercased name) and MENTIONS edges.
  • L197 NEXT edges give reading order between chunks.
  • L204 Concepts that co-occur in a chunk get a RELATED_TO edge. No weight yet (it would double-count on re-index).
  • L244 One LLM call per chunk, 3 in flight. Small models could not keep several excerpts apart, so batching was dropped. Failures are counted, and the note's hash is only stored when none failed, so a failed note is retried on the next index.
  • L287 Tolerant parser: accepts strings or {concept|name|term} objects, because gemma3:1b ignored the requested shape. Returns null (a failure) for unusable replies, and an empty list is a valid result.

Say this when explaining

  • The user doesn't reorganize anything. The graph is built from messy notes automatically: headings become chunks, wikilinks become LINKS_TO edges, an LLM names the concepts.
  • Hashing means re-indexing only touches changed notes.

Honest caveats

  • Concept extraction is one LLM call per chunk. A huge file on local Ollama will be slow on first index.
  • RELATED_TO has no weight, which was a deliberate cut.
  • Link targets that aren't indexed yet are created as placeholder Note nodes without a hash; the hash lookup ignores them.

13/** Splits markdown by heading, then packs paragraphs/bullets up to ~MAX_CHUNK chars. */
14export function chunkMarkdown(md: string): RawChunk[] {
15  const body = md.replace(/^---\n[\s\S]*?\n---\n/, "");
16  const sections: { heading: string; lines: string[] }[] = [{ heading: "", lines: [] }];
17  let inFence = false;
18  for (const line of body.split("\n")) {
19    if (line.trim().startsWith("```")) inFence = !inFence;
20    const h = !inFence && /^#{1,6}\s+(.*)$/.exec(line);
21    if (h) sections.push({ heading: h[1].trim(), lines: [] });
22    else sections[sections.length - 1].lines.push(line);
23  }
24 
25  const chunks: RawChunk[] = [];
26  for (const sec of sections) {
27    // blocks separated by blank lines; a long list of bullets still splits at the size limit below
28    const blocks = sec.lines.join("\n").split(/\n\s*\n/).map((b) => b.trim()).filter(Boolean);
29    let cur = "";
30    const flush = () => {
31      if (cur.trim().length > 20) chunks.push({ heading: sec.heading, text: cur.trim() });
32      cur = "";
33    };
34    for (const block of blocks) {
35      for (const piece of splitLong(block)) {
36        if (cur && cur.length + piece.length > MAX_CHUNK) flush();
37        cur += (cur ? "\n\n" : "") + piece;
38      }
39    }
40    flush();
41  }
42  return chunks;
43}
44 
45function splitLong(block: string): string[] {
46  if (block.length <= MAX_CHUNK) return [block];
47  const out: string[] = [];
48  let cur = "";
49  for (const line of block.split("\n")) {
50    if (cur && cur.length + line.length > MAX_CHUNK) {
51      out.push(cur);
52      cur = "";
53    }
54    cur += (cur ? "\n" : "") + line.slice(0, MAX_CHUNK * 2);
55  }
56  if (cur) out.push(cur);
57  return out;
58}

60export function hashText(s: string): string {
61  let h = 5381;
62  for (let i = 0; i < s.length; i++) h = ((h << 5) + h + s.charCodeAt(i)) | 0;
63  return `${s.length}:${h}`;
64}

239  /**
240   * Asks the LLM for key concepts, one chunk per call (small local models can't keep several excerpts apart).
241   * `failed` counts chunks whose extraction errored or was unparseable after a retry, so the caller can
242   * avoid marking the note as fully indexed.
243   */
244  private async extractConcepts(chunks: RawChunk[]): Promise<{ concepts: string[][]; failed: number }> {
245    const concepts: string[][] = chunks.map(() => []);
246    let failed = 0;
247    let next = 0;
248    const worker = async () => {
249      while (next < chunks.length) {
250        const i = next++;
251        const got = await this.extractOne(chunks[i]);
252        if (got === null) failed++;
253        else concepts[i] = got;
254      }
255    };
256    await Promise.all(Array.from({ length: CONCEPT_CONCURRENCY }, worker));
257    return { concepts, failed };
258  }

288  const match = /[{[][\s\S]*[}\]]/.exec(reply);
289  if (!match) return null;
290  let raw: unknown;
291  try {
292    const parsed = JSON.parse(match[0]);
293    raw = Array.isArray(parsed) ? parsed : parsed?.concepts;
294  } catch {
295    return null;
296  }
297  if (!Array.isArray(raw)) return null;
298  const names = raw.map((x: unknown) => {
299    if (typeof x === "string") return x;
300    if (x && typeof x === "object") {
301      const o = x as Record<string, unknown>;
302      const v = o.concept ?? o.name ?? o.term ?? o.title;
303      return typeof v === "string" ? v : "";
304    }
305    return "";
306  });
307  const clean = names.map((n) => n.trim().toLowerCase()).filter((n) => n.length > 1 && n.length < 60);
308  return [...new Set(clean)].slice(0, 8);
309}

10  async start(): Promise<void> {
11    this.stream = await navigator.mediaDevices.getUserMedia({ audio: true });
12    this.chunks = [];
13    this.rec = new MediaRecorder(this.stream);
14    this.rec.ondataavailable = (e) => e.data.size && this.chunks.push(e.data);
15    this.rec.start();
16  }
17 
18  stop(): Promise<Blob> {
19    return new Promise((resolve, reject) => {
20      const rec = this.rec;
21      if (!rec) return reject(new Error("Not recording"));
22      rec.onstop = () => {
23        this.stream?.getTracks().forEach((t) => t.stop());
24        resolve(new Blob(this.chunks, { type: rec.mimeType || "audio/webm" }));
25      };
26      rec.stop();
27    });
